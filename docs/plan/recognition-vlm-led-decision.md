# 户型图识别架构决策：VLM 主导识别，CV 退出识别主体

> 状态：**决策记录 2026-09-01**（对应 v2 方案的识别轨角色调整）
> 依据：`fp-101` 真值 + 带 VLM 的端到端实测三边对照
> 关联：`docs/plan/floorplan-recognition-v2.md`

## 0. 结论

**识别（房间 + 门窗）以视觉大模型（VLM）为主导**。CV 从"识别主体"降级为**可选的几何校验与降级兜底**，不再作为房间/门窗的识别来源。

本决策依据一次真实对照：在 `fp-101` 上，VLM 的识别质量显著优于现有确定性 CV 管线。

---

## 1. 实测证据（fp-101，真值 9 房 / 17 开口）

### 1.1 房间识别

| 来源 | 结果 | 与真值核对 |
|---|---|---|
| **VLM** | 9 个房间（bedroom×3 / livingDining / balcony / bathroom×2 / kitchen / other） | **9/9 全部命中**，房间数 100% 正确 |
| **CV**（polygonize_rooms） | 依墙图闭合，`fp-101` 曾只闭合 1-2 房 | 明显漏检、无法形成完整房间 |

### 1.2 门窗识别

| 来源 | 结果 | 说明 |
|---|---|---|
| **VLM** | 12 个开口（4 窗 + 7 门 + 1 可疑） | 门窗**定位合理**、类型判断基本正确（部分带门弧/门扇/平行线证据） |
| **CV**（wall_graph 物理缺口） | **仅 3 个缺口**（872/347/465mm） | 只把"墙段完全断开"当缺口，**无法识别连续墙带上的门/窗洞** |

### 1.3 端到端 benchmark（assisted，含 VLM）

```
Room mIoU:         0.9377   ✅ ≥0.9 达标
Room Count Accuracy: 1.0    ✅ 达标
Openings F1:       0.0      ❌ 唯一卡点
JSON Effective Rate: 1.0    ✅
```

**关键事实**：房间识别已达标（mIoU 0.94 / 房间数 100%）。唯一失败项 openings F1 的根因是 **CV 缺口检测只覆盖 3/17**——VLM 已给出 12 个合理开口，却被 F3 的"必须对应 CV 缺口"硬条件全部拒绝。

---

## 2. 为什么让 VLM 主导

1. **CV 缺口的语义缺陷**：真正户型图的窗/门大量位于**连续墙带上的开洞**，不是墙段断裂。现有 `build_wall_graph` 只识别"断裂缺口"，天然漏窗漏门。这不是调参能补的，是**识别语义的根本缺口**。
2. **VLM 具备语义能力**：VLM 能理解"这是窗（平行细线）"、"这是门（门弧/门扇）"，且定位合理——这正是 CV 缺乏的语义判断。
3. **真实对照已证明**：VLM 房间全对 + 开口 12 个合理，远优于 CV 的 3 缺口。

---

## 3. 目标架构：VLM 主导，CV 退为校验/兜底

```text
输入图
  → VLM 识别（主导）  VlmDraft：rooms / openings / scales
  → Schema/Pydantic 校验（强制，防越界/自交/枚举）
  → 极简几何门禁（取代原 CV-WallGraph 级校验）:
       · 房间不自交、面积>0、多边形有效
       · 开口两端在同一房间边界附近、宽度落在物理范围(300~3000mm)
       · 比例尺：VLM scale 中位数/MAD 拟合（无 CV 墙厚自举交叉时以 VLM 为准）
  → LayoutRevision / DerivedRoomSet（VLM 多边形直接作为房间几何，吸附到最邻近房间边界作轻度规整，不强依赖 CV 墙轴）
  → 下游 3D / 全景（scene_geometry → cubemap → 中转站渲染 → 超分）
```

**CV 的新角色（保留但不作识别主体）**：
- 可选**比例尺自举**兜底（当 VLM 无 usable scale 时）
- 可选**坐标轻吸附**（规整 VLM 多边形，遇到高置信墙轴才吸附，避免跳墙）
- **降级路径**：VLM 不可用/超时 → 仍返回结构化 `needsReview`，**不发布错误 Revision**

---

## 4. CV 识别的取舍

| 原 CV 能力 | 处置 |
|---|---|
| `wall_graph` 缺口检测（门窗来源） | **从识别主体移除**（漏检严重）；不作开口确认的必要条件 |
| `polygonize_rooms`（房间闭合） | 移除为主识别来源；仅作 VLM 不可用时兜底 |
| `fusion.*` F3 开口仲裁（依赖 CV 缺口） | **重构**：开口确认改为「VLM 开口 + 房间边界/物理宽度/证据门」，不再要求对应 CV 缺口 |
| `build_scene_geometry`（3D 建模） | **保留**（它消费 LayoutRevision，与识别轨解耦，是确定性可验证环节） |
| 比例尺 `calibrate_scale` | 保留为 VLM scale 兜底/交叉校验 |

**不再删除**：VLM 输出仍必须过**最低几何门禁**（自交/越界/枚举/面积/宽度/比例合理性），因为"低置信不发布"架构边界不变。只是这个门禁不再以 CV 墙图为主体。

---

## 5. 迁移步骤

1. **重构 F3 开口仲裁**：`fusion_openings` 的"必须命中 CV 缺口"改为"锚定最近房间边界 + 宽度在物理范围 + 证据门（门弧/门扇→door，平行线→window）"。CV 缺口仅作**加分证据**，非必要条件。
2. **房间几何**：VLM 多边形直接作为 `DerivedRoom`；轻度规整（去共线/轻微正交化）但**不强吸到 CV 墙轴**（避免因 CV 轴不准把好房间拉歪）。
3. **比例尺**：VLM scale 取中位数/MAD，VLM 无则用 `calibrate_scale` 兜底。
4. **门禁**：保留 Pydantic + 自交/面积/宽度/同房间边界校验，作为发布前的最后防线。
5. 用 `fp-101` 重新 benchmark，验证 openings F1 是否提升（预期从 0 大幅上升），记录前后对照。

---

## 6. 风险与回退

| 风险 | 对策 |
|---|---|
| VLM 坐标漂移（多边形/开口离墙） | 最低几何门禁：开口两端须在同一房间边界附近（容差按墙厚归一化），否则 `needsReview` 不发布 |
| VLM 漏检开口（VLM 12 vs 真值 17，漏 5） | 不追求"全召回"；漏检进 `OpeningCandidateSet` 供人工/复核，**不以漏检判定失败** |
| VLM 自陈 confidence=0（当前保守） | `confidence` 不参与发布门（架构不变），只作候选排序提示 |
| 无 CV 校验，误发布 | 保留同房间边界/物理宽度/自交门禁；任一项不满足 → 只进候选/`needsReview` |
| VLM 间歇不可用（SSL/超时） | 降级：结构化 `needsReview` + CV 兜底，绝不发布半成品 |

**回退**：若 VLM 主导导致误发布或精度倒退，回退到「CV 校验 + VLM 候选」的 ASSISTED 模式；VLM 主导作为主路径的候选，需在留出集上复验。
