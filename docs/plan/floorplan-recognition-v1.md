## 1. 诊断：当前不是"精度略低"，而是识别链路缺失

以下五条均为本次在仓库和真实图像上复现的证据，不是推测。

### D-01 通用识别算法不存在

仓库里唯一的图像识别函数是 `detect_door_arc_proposals()`。墙和房间**没有任何自动提取代码**：

- `scripts/build_fp001_manual_revision.py:33-59` 是 **25 段手工敲入的墙中心线坐标**。
- 同文件 `:61-67` 是 **5 个手工敲入的房间**。
- 窗：**没有检测器**。`cluster_collinear_window_lines()` 只是一个纯函数，接收 `Line2D` 列表，而仓库中没有任何代码从图像生成这个列表。

因此"识别率"目前无法外推到任意户型图。`docs/2026-08-25_评测-桌面户型压缩包-report.md` 的 F-01 已经记录了这一点：9 张样本端到端覆盖 **0/9**。

### D-02 门检测把最不可靠的信号当作主信号

当前顺序是 **先 HoughCircles 找圆 → 再做拓扑过滤**。圆弧是门的*装饰性*表现，圆形家具（马桶、洗手盆、灶眼、圆桌）会大量触发。

在 fp-001 上实测，当前检测器返回 8 个提议：

| 提议中心 | 半径 | 实际是什么 |
|---|---|---|
| (478,214) (482,210) (480,224) | 8–14 | 卫生间马桶与洗手盆 |
| (474,248) (476,306) | 8 | 厨房灶眼 |
| (218,352) (212,356) | 8–11 | 客厅家具/窗线 |
| (436,236) | 27 | 疑似真实门弧 |

8 个提议里约 1 个是门。这与基准集 `test precision 0.56` 完全一致（`docs/data/door-detection-benchmark.v1.json`）。

**正确的主信号是墙带上的缺口**：每一个门和窗在构造上都必然是墙带的缺口，缺口召回接近 1.0；圆弧、细线组只应作为**分类证据**，不应作为提议源。这一反转是本方案最大的精度杠杆。

### D-03 光度阈值写死，且对本数据集是错的

`opening_detection.py` 中：

- `:156` `dark = (grayscale < 80)`
- `:260` `patch.min() < 110`

fp-001 实测：Otsu 阈值为 **167**，墙体灰度落在 **60–150**。图像有 JPEG 压缩退化，抗锯齿边缘灰度在 100–150。

后果：`< 80` 会静默丢弃大量墙体像素。本次实测，把二值化换成 Otsu 后，最大墙连通域从 3592 px 提升到 **7469 px**，连通域数量从 26 降到 23。

### D-04 几何阈值绑定图像尺寸而非图纸自身

`:139-142`：

```python
scale = short_edge / 800
min_radius = max(4, round(8 * scale))
```

半径阈值由**图片像素尺寸**推导。同一套户型图导出成 800px 或 1600px，检测行为就会改变。正确做法是从图纸自身的**墙厚**推导 mm/px，再用毫米阈值。

### D-05 没有可测量 90% 的真值数据

`户型.zip` 的 9 张原图与 58 个红框门标注解压在系统临时目录，**该目录已被清理**，本次全盘检索未找到。仓库中只保留了聚合指标与 SHA-256。

仓库现存 3 张图，其中只有 fp-001 在本次范围内；且 fp-001 的"真值"（`rooms.manual-v2.json`）是人工目测敲入的，与被评测对象同源，**存在循环验证问题**。

> **这是达成 90% 的硬前置条件。** 算法可以先建，但"识别率 90%"在拿到独立真值集之前不可测量、不可声明。

## 2. 验收指标（沿用 P0-04 已冻结门槛，不另立标准）

| 指标 | 门槛 | 定义 |
|---|---|---|
| Room mIoU | ≥ 0.90 | 预测房间多边形与真值的平均 IoU（一对一匈牙利匹配） |
| 房间数完全正确率 | ≥ 90% | 每张图房间数与真值完全一致的图占比 |
| 邻接边 F1 | ≥ 0.95 | 房间邻接关系图的边 F1 |
| 门窗 F1 | ≥ 0.90 | 分类别（door/window）各自 F1，取加权 |
| 比例尺相对误差 | P90 ≤ 5% | mm/px 与真值之比 |
| 墙中心线误差 | 中位 ≤ 0.5×墙厚 | 匹配墙段的中心线偏移 |

**切分纪律**：测试集不参与任何阈值选择。沿用报告中已有的 6/3 训练-留出划分方式。

## 3. 目标架构

```text
S0  归一化与输入门禁
      解码 → 去白边 → 去斜 → Manhattan 置信度 → 可读性门禁
S1  笔画分析
      Otsu/自适应二值化 → 距离变换 → 笔画半径直方图
      → 自动墙厚 r_wall → mm/px 自举
S2  结构层 / 标注层分离
      厚笔画=墙（测地重建）  细笔画=尺寸线/文字/家具/窗扇/门弧
      → 剔除图框外尺寸标注
S3  墙图向量化
      轴向带提取 → 中心线段 → 1D 轴聚类（Manhattan 正则化）
      → 吸附/合并/延伸至交点 → 平面墙图（节点+边+厚度）
S4  房间多边形
      polygonize → 去外环/去碎面 → 正交吸附 → 面积
S5  开口检测（缺口优先）★核心反转
      沿每条墙边采样占空 → 缺口区间（召回≈1.0）
      → 用标注层证据分类：门弧/门扇→door，细线组→window，无证据→doorway
S6  房间语义
      标签词典匹配（卧室/客厅/厨房/卫生间/餐厅/阳台/书房）
      → 洁具图元、面积、邻接先验兜底
S7  置信度与复核路由
      低置信 → OpeningCandidateSet（不进入 LayoutRevision）
```

### S0 输入门禁的修正

当前 `短边 < 1200px → needsReview` 使 9 张视觉清晰的 ~800px 样本自动覆盖率为 0（报告 F-02）。

替换为**可读性门禁**，三个可测量条件：

- 实测墙笔画半径 `r_wall ≥ 1.5px`（保证墙带可分辨）
- 墨迹占比在 1%–15%（排除空白图与过曝/全黑图）
- Manhattan 置信度 ≥ 0.9（主梯度方向能量集中于 0°/90°）

只有独立测试集验证通过后才下调阈值——不通过放大图像绕过。

### S1 自动墙厚与比例尺自举

距离变换的笔画半径直方图在本数据上是**清晰双峰**（fp-001 实测）：

| 半径 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 像素数 | 9461 | 2160 | 1623 | 1289 | 163 |

半径 1 = 文字、尺寸线、家具、窗扇；半径 ≥2 = 墙。对该直方图再做一次 Otsu 即得 `r_wall`，无需任何写死常数。

比例尺自举：无 OCR 尺寸时，取内隔墙厚 ≈ 100–120mm，得 `mm_per_px ≈ 110 / (2·r_wall_interior)`；有 OCR 尺寸标注时以 `calibrate_scale()` 的多约束鲁棒拟合为准，自举值仅作交叉校验。这样彻底移除 `short_edge/800`。

### S3 Manhattan 正则化是连通性的关键

本次实测：墙像素天然是**碎的**（fp-001 有 23 个连通域），因为门窗在构造上就切断了墙。直接对墙像素求连通域或直接 `polygonize` 都会失败——这正是当前代码走不通的原因。

正确做法是在**向量域**闭合：

1. 收集所有竖直墙带中心 x 坐标 → 以 `r_wall` 为容差做 1D 聚类 → 得到规范 x 轴集合；水平同理得 y 轴集合。
2. 每段墙吸附到最近规范轴。
3. 每段墙向两端**延伸**到最近的规范正交轴，延伸预算 ≤ 最大门宽（像素）。
4. 交点建节点，得到闭合平面图。

延伸掉的那段"虚拟墙"要**记录下来**——它正是 S5 的缺口候选，两个阶段共用同一份证据。

### S5 缺口优先的开口检测

对墙图中每条边：

1. 沿中心线以 `2·r_wall` 宽度采样墙掩膜占空率。
2. 取占空率低于阈值的极大区间为**缺口**，宽度落在 [500mm, 3000mm] 的进入候选。
3. 在**标注层**（S2 保留的细笔画）中，于缺口邻域取证据：

| 证据 | 判定 |
|---|---|
| 四分之一圆弧（半径≈缺口宽，圆心在缺口端点） | `door` |
| 直线门扇（锚在缺口端点，与墙成 45°–90°） | `door` |
| 2–4 条平行于墙的细线跨越缺口 | `window` |
| 无证据、宽度在门宽区间、两侧均为房间 | `doorway`（垭口） |
| 缺口位于墙图边界外侧 | 非开口，丢弃 |

4. 置信度 = f(缺口锐利度, 证据强度, 两侧房间成立, 宽度合理性)。

这样 `cluster_collinear_window_lines()`、`is_door_rect_pair()`、`choose_single_door_origin()` 这些已有但从未被真实数据调用的规则，第一次接入真实输入。

**架构不变量保持不变**：低置信开口只进 `OpeningCandidateSet`，不进 `LayoutRevision`。这是仓库已经做对的部分（Revision 2 的教训，v3.1 文档第 716 行），不动它。

## 4. 分阶段实施

| 阶段 | 交付物 | 完成定义 |
|---|---|---|
| **P1 地基与量尺** | `floorplan/preprocess.py`（二值化、笔画分析、门禁）、`floorplan/metrics.py`、标注 Schema、`scripts/benchmark_floorplan.py` | 能对任意一张图输出 `r_wall`/mm-px/门禁判定；量尺能在给定真值上算出全部 §2 指标 |
| **P2 墙与房间** | `floorplan/wall_graph.py`、`floorplan/rooms.py` | fp-001 房间数正确、mIoU 可测；输出可视化叠加图 |
| **P3 开口** | `floorplan/openings.py`（缺口优先 + 证据分类） | 门窗分类别 F1 可测；旧 `detect_door_arc_proposals` 降级为证据函数 |
| **P4 语义与置信** | 标签词典、洁具先验、置信度门 | 房间类型准确率可测；低置信正确路由到候选集 |
| **P5 调优与接线** | 阈值在训练集上选定、接入 Command Facade `parse` | 留出测试集达到 §2 全部门槛；`LayoutRevision` 由算法而非手敲坐标生成 |

阈值只在训练切片上选，留出集单次评估。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **真值集缺失**（D-05） | 90% 不可测量 | **最高优先级**：请用户重新提供 `户型.zip`，并补充墙/房间/窗标注（现有红框只覆盖门）。在此之前所有指标标记 `notEvaluated` |
| 样本量不足（现存 1 张在范围内） | 阈值过拟合 | 按 P0-02，PoC 补到 30 张，发布前独立测试集 200 张，按来源/户型族隔离 |
| 开放式空间（客餐厅连通）房间数歧义 | 房间数正确率失真 | **已冻结**：`docs/plan/annotation-spec-v1.md` R-01（有门扇/门弧算分房，doorway 不算，但照标），指标随之定义 |
| 图纸含家具/洁具图元 | 干扰细线证据层 | 洁具在标注层内做形状先验剔除；不影响缺口主信号 |
| JPEG 退化严重的图 | 二值化不稳 | Otsu + 局部自适应取并集；门禁兜底 |
